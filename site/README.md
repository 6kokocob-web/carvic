# CARVIC (ООО "Карвик") — прототип сайта автозапчастей

Статический фронтенд-прототип интернет-магазина автозапчастей (опт и розница) по функциональному образцу rossko.ru.
Vanilla JS, без сборки и внешних зависимостей (шрифт Montserrat, OFL, лежит в `assets/fonts`).
Макет — утверждённый `layout-v18.jpg` (фиксированный баннер, узкая тёмная левая панель, белая рабочая область).

## Запуск

Рабочий запуск всего черновика, включая read-only поиск ROSSKO — из корня проекта, не из `site/`:

```bash
ROSSKO_MOCK=1 node server/index.js
# http://127.0.0.1:43123/
```

Только вёрстка, без API поставщика:

```bash
cd site
python3 -m http.server 8080
# открыть http://localhost:8080
```

Ключи `ROSSKO_KEY1` / `ROSSKO_KEY2` в репозиторий не входят. Живой `GetSearch` и ограничения описаны в `../README.md` и `../docs/ROSSKO.md`.

> ⚠️ **Dev note:** каталог товаров, цены, остатки, применимость, расшифровка VIN, контрагенты, типы цен и скидки —
> **демонстрационные данные (mock)**. Реальны только реквизиты и контакты компании (`COMPANY` в `js/data.js`).
> Демо-входы (контрагент: код `demo`; админка: `admin` / `demo`) **не имеют реальной безопасности**.

## Что реализовано

- **Баннер** (146 px, фиксированный): логотип CAR**VIC** / АВТОЗАПЧАСТИ, 4 иконки-категории (свеча, диск, привод, поршень),
  поле «ВИН или артикул» (17 символов → VIN, иначе — поиск по артикулу/OEM/названию), телефон, корзина со счётчиком.
- **Левая панель:** Марка / Модель / Год, чекбоксы «Категории» и «Производители», блок «Покупатель» (гость / контрагент),
  выбор торговой точки по умолчанию, навигация по разделам.
- **Главная:** интерактивная SVG-схема седана с красными точками (электрика, двигатель, фильтры, кузов, охлаждение,
  тормоза, трансмиссия, подвеска, выхлоп) — клик фильтрует «Результаты»; карточки с превью, брендом, артикулом/OEM,
  **остатками по каждой точке**, ценой и кнопкой «В корзину»; сортировка, пагинация.
- **VIN** (`#/vin/<VIN>`): валидация, демо-расшифровка (WMI + символ года), подбор деталей, переход к схеме.
  Демо-VIN: `JTNB11HK103456789`, `Z94K241CBNR123456`, `XTAGFK330NY654321`.
- **Каталог** (`#/catalog`, `#/catalog/<группа>`), **поиск по артикулу/OEM** (`#/search?q=`), **карточка товара** (`#/part/<sku>`)
  с остатками по точкам, выбором точки и пошаговым расчётом цены.
- **Корзина** (localStorage): шторка + страница `#/cart`; у каждой позиции **outletId — точка списания** (можно сменить,
  видно остаток, предупреждение «под заказ»). **Оформление** `#/checkout`: имя, телефон, email, комментарий,
  розница/опт (организация, ИНН), **выбор точки выдачи**, опция «списать все позиции с этой точки»; заказ уходит в
  `OneC.createOrder` (mock) с `counterpartyId`, показывается сообщение об успехе.
- **Вход контрагента** (`#/login`, демо): после входа во всём сайте (каталог, корзина, заказ) — цены контрагента.
- **Страницы:** Торговые точки (3 точки, телефон, «уточняйте по телефону», ссылки на Яндекс.Карты), Оптовикам,
  Доставка и оплата, О компании, Контакты, Реквизиты (с копированием), подвал.
- **Админка** `#/admin` (демо, `admin`/`demo`): товары и базовые цены по каждому типу цены; типы цен (добавление,
  переименование); справочник контрагентов с привязкой типа цены; скидки % по группам товаров для контрагента;
  индивидуальные цены контрагента; «Расчёт цены» с пошаговым объяснением; журнал «отправлено в 1С».
- Адаптив (бургер-меню на мобильных), без ошибок в консоли (проверено headless Chrome).

## Слой данных 1С (`js/api/onec.js`)

UI получает цены и остатки **только** через `window.OneC` — в разметке и в `data.js` цен нет
(mock-базовые цены лежат в служебной таблице `__MOCK_1C_BASE_PRICES`, которую читает только mock-слой).

Интерфейс (все методы → Promise):

| Метод | Назначение |
|---|---|
| `getOutlets()` | торговые точки |
| `getStock(outletId, sku)`, `getStockAll(sku)`, `getStocks(skus)` | остатки по точкам |
| `getPrice(sku, counterpartyId?)`, `getPrices(skus, counterpartyId?)`, `explainPrice(...)` | итоговая цена + источник + шаги расчёта |
| `getPriceTypes()`, `savePriceType({id?, name, defaultPercent})` | типы цен (Розница, Опт 1, Опт 2…) |
| `getBasePrice(sku, priceTypeId)`, `setBasePrice({sku, priceTypeId, value})` | базовые цены по типу |
| `setPrice({sku, counterpartyId, value})`, `removePrice(...)`, `getIndividualPrices(cpId?)` | индивидуальные цены |
| `setGroupDiscount({counterpartyId, productGroup, discountPercent})`, `getGroupDiscounts(cpId?)` | скидки по группам |
| `getCounterparties()`, `getCounterparty(id)`, `saveCounterparty(...)`, `loginCounterparty(id, code)` | контрагенты |
| `createOrder({outletId, items:[{sku, qty, outletId}], customer, counterpartyId})` | заказ |
| `getPriceLog()`, `resetMock()` | журнал mock-«отправок в 1С», сброс демо-данных |

**Модель цен:**
- Цена **не зависит от торговой точки** — изменение в админке действует сразу во всех точках. `outletId` используется
  только для остатков и списания позиций заказа.
- У каждого контрагента свой **тип цены**; гость — «Розница».
- **Порядок расчёта `getPrice(sku, counterpartyId)`:**
  1. индивидуальная цена контрагента на товар (если есть) — без дополнительных скидок;
  2. иначе базовая цена по типу цены контрагента − скидка % по группе товара (если задана), округление до 1 ₽.
- Для товаров без собственной цены оптового типа mock использует демо-правило «розница − N %» (`defaultPercent` типа).

**Mock:** всё хранится в localStorage браузера; каждая запись логируется в консоль и журнал как «отправлено в 1С».
1С должна быть **мастер-системой цен**: в рабочей версии сайт сохраняет изменение через 1С и показывает его только после
успешного ответа — так цены в 1С и на сайте всегда совпадают.

### Целевая интеграция: 1С:УНФ (облако)

Способ обмена **уточняется**: стандартный REST-интерфейс **OData** УНФ (`/odata/standard.odata/…`) и/или
**HTTP-сервисы** УНФ (расширение). Рекомендуется backend-прокси на carvic.ru между сайтом и 1С.
Структура слоя соответствует сущностям УНФ (точные имена объектов — по публикации OData):

| Сайт | 1С:УНФ |
|---|---|
| товар / SKU, группа товара | Справочник **Номенклатура** (артикул, группа номенклатуры) |
| торговая точка `outletId` | **Склады / Структурные единицы** |
| остатки | **Остатки** — регистр «Запасы» по структурной единице (с учётом резервов) |
| типы цен, базовые цены | **Типы цен**, регистр «Цены номенклатуры», документ «Установка цен номенклатуры» |
| контрагент, его тип цены | Справочник **Контрагенты** (тип цен — из договора/соглашения) |
| скидки по группам | скидки (наценки) УНФ с условием по контрагенту и группе номенклатуры — механизм уточняется |
| индивидуальные цены | отдельный тип цен контрагента / регистр цен контрагентов — уточняется |
| `createOrder` | документ **Заказ покупателя** (контрагент, структурная единица, вид цен, ТЧ «Запасы» с резервом по `item.outletId`) |

При подключении меняются только тела методов в `onec.js` — сигнатуры и UI остаются прежними.

## Следующие шаги

1. **Backend** (Node.js/PHP/Python) на carvic.ru: прокси к 1С:УНФ, авторизация контрагентов и сотрудников (вместо демо-входов),
   приём заказов, уведомления менеджеру на почту, защита персональных данных (152-ФЗ, политика ПДн).
2. **Интеграция с 1С:УНФ** — согласовать OData/HTTP-сервисы, выгрузку номенклатуры, остатков, типов цен, контрагентов; загрузку заказов.
3. **Каталог поставщиков.** Read-only `GetSearch` ROSSKO уже вынесен в серверный адаптер (`server/rossko.js`): артикул, бренд, склады, кроссы. Заказы поставщику, другие методы и другие поставщики не подключались. Цены ROSSKO не являются розницей CARVIC и не пишутся в слой 1С.
4. **Декодирование VIN:** коммерческий VIN-сервис / каталоги OEM (Laximo, Parts-Catalogs и др.), реальная применимость по модели и году.
5. **Контент:** брендбук (цвета/шрифты — только переменные в `css/style.css`), режим работы точек, условия доставки и оплаты,
   фото магазинов, координаты для карт (виджет Яндекс.Карт).
6. **Хостинг на carvic.ru:** статика (nginx / любой хостинг) + HTTPS (Let's Encrypt), backend отдельно; SEO (ЧПУ вместо hash-роутинга,
   sitemap, микроразметка), Яндекс.Метрика.
